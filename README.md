# Лабораторная работа №6: Ретро-Фронтенд — Формы и Адаптивная верстка

Добро пожаловать в проект-реставрацию! Данная лабораторная работа посвящена изучению интерактивных элементов веб-форм, семантическому проектированию интерфейсов и реализации адаптивной блочной разметки средствами HTML5 и CSS3.

## 🎭 Легенда проекта «Машина Времени»

К нам поступил заказ от руководителя IT-компании, у которого случился приступ ностальгии по эпохе зарождения Рунета — середине 2000-х годов. Он хочет воссоздать на своём новом проекте легендарную первую форму регистрации **"ВКонтакте.ру"** образца 2006 года. 

Исходный код тех времён, разумеется, безвозвратно утерян. На руках у заказчика остались всего два артефакта, которые он нам и передал:
1. **Один-единственный скриншот** (`images/screenshot.png`) того, как эта форма выглядела в окне старого браузера.
2. Оригинальная иконка логотипа **`Vkontakte.gif`** размером 32х32 пикселя (лежит в папке `images/`).

## 📋 Техническое задание

Ваша задача — выступить в роли фронтенд-археологов. Полагаясь **исключительно на предоставленный скриншот**, вы должны воссоздать этот интерфейс.

### Критерии оценки и требования к коду:

1. **Pixel-Perfect соответствие (Десктоп):** Заказчик — бескомпромиссный перфекционист. Верстка на экранах мониторов должна визуально совпадать со скриншотом пиксель в пиксель. Шрифты, их цвета, размеры полей ввода, выравнивание текстовых подсказок и геометрия кнопки должны идеально встать на свои исторические места. Любые визуальные смещения — автоматический возврат проекта на доработку.
2. **Семантика HTML5:** Использовать древнюю верстку на таблицах (`<table>`) или устаревшие презентационные теги (вроде `<font>`) **категорически запрещено**. Код под капотом должен быть семантически чистым. Все подписи к полям должны быть размечены через `<label>` и жестко связаны с элементами управления. Кнопка отправки формы должна быть реализована через валидный тег `<button>`.
3. **Контроль побочных эффектов (CSS):** При написании стилей запрещено использовать слепые общие сокращения (например, свойство `background`), если вам требуется изменить только одно значение (например, `background-color`). Задумывайтесь о методе объявления каждого свойства.
4. **Адаптивный лад (Mobile):** Заказчик будет проверять эту форму в том числе со своего смартфона. Вы обязаны заставить этот интерфейс из 2006 года адекватно складываться в адаптивный мобильный макет без появления горизонтальной полосы прокрутки.

## 🚀 Инструкция по сдаче работы (GitHub Workflow)

Репозиторий является открытым. Сдача работы происходит строго через систему контроля версий Git и механизм **GitHub Pull Request**:

1. Сделайте **Fork** этого репозитория в свой личный аккаунт GitHub.
2. Склонируйте форкнутый репозиторий на рабочий компьютер.
3. В VS Code создайте новую рабочую ветку **`homework-06`**.
4. В корневой директории репозитория создайте персональную папку. Имя папки должно строго соответствовать формату: **`Фамилия_Имя_Группа`** (например, `Ivanov_Ivan_PPOIS-3`).
5. Скопируйте исходную иконку из общей папки к себе и ведите всю разработку (`index4.html`, файлы CSS) **строго внутри своей персональной папки**.
6. Разрабатывайте проект итеративно. Сделайте не менее **3 осмысленных коммитов** в историю ветки, отражающих этапы вашей работы (коммиты, заливающие весь готовый код одним разом за 1 минуту до дедлайна, не принимаются).
7. Отправьте ветку в свой форк и откройте **Pull Request (PR)** в ветку `main` оригинального репозитория.
